# Резервная копия и безопасное восстановление

`SqliteBackupService` не копирует открытый файл обычной файловой операцией. SQLite
сама создаёт согласованный снимок командой `VACUUM INTO`. Метод возвращает путь
только после повторного открытия копии и проверки её содержимого.

## Критерии готовности копии

Копия считается готовой, если одновременно выполнены условия:

1. SQLite открыла файл отдельным соединением.
2. `PRAGMA integrity_check` вернул `ok`.
3. Прочитана версия схемы.
4. Все тренировки прочитаны в устойчивом порядке.
5. Сформированы число записей и SHA-256 их значимых полей.

Само наличие файла не означает успешного backup.

## Безопасное восстановление

Восстановление разрешено только в новый отдельный файл. Сервис отказывается
использовать путь рабочей базы, существующую цель или сам backup как цель. Сначала
проверяется исходная копия, затем SQLite создаёт восстановленную базу, после чего
версия схемы, число строк и SHA-256 сравниваются с backup.

Рабочая база при проверке восстановления не изменяется. Пользователь должен:

- закрыть приложение перед реальным восстановлением;
- сохранить текущую рабочую базу отдельно;
- сначала восстановить backup в тестовый каталог и проверить записи;
- не заменять рабочий файл непроверенной копией;
- хранить backup отдельно от каталога приложения и рабочей базы.

Автоматическая проверка использует только временные каталоги JUnit.
