# Транзакции, миграции и CSV-импорт

`WorkoutCsvImporter` сначала читает и проверяет весь файл. Лишь после успешного
преобразования всех строк он вызывает `WorkoutRepository.saveAll`.

SQLite-репозиторий отключает `autoCommit`, вставляет каждую тренировку одним
`PreparedStatement` и выполняет `commit` только после всего пакета. При SQL-ошибке
выполняется `rollback`, а причина с кодом проблемной строки передаётся вызывающему коду.

`SqliteMigrator` хранит текущий номер в `schema_version`. Миграция `V002` добавляет
столбец `comment TEXT NOT NULL DEFAULT ''`. Значение по умолчанию делает миграцию
безопасной для старых строк. После успеха фиксируется версия 2, поэтому повторный
запуск не пытается добавить столбец снова.

## Ответы для защиты

1. Первая строка исчезает при ошибке второй, потому что обе вставки входят в одну
   неподтверждённую транзакцию, которую отменяет `rollback`.
2. Скрытую ошибку могла бы вызвать строка с `;` внутри типа тренировки: упрощённый
   разбор мог бы сместить поля. Такой ввод явно отклоняется.
3. В трекере контракт получил операцию `saveAll(List<Workout>)`: либо сохраняется весь
   пакет тренировок, либо состояние репозитория не меняется.
