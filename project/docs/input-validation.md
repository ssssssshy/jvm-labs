# Проверка ввода и доступность

## Матрица ввода

| Ввод | Ожидаемое поведение | Состояние данных |
|---|---|---|
| Пустой тип | Сообщение «Введите тип…», фокус в поле | Таблица не меняется |
| Только пробелы | То же сообщение; ошибка передаётся текстом и рамкой | Таблица не меняется |
| Тип длиннее 60 символов (аналог недопустимого кода) | Просьба сократить значение | Таблица не меняется |
| Корректный тип, дата и состояние | Сообщение об успехе | Добавлена ровно одна запись |
| Дата не выбрана | Сообщение «Выберите дату…», фокус на дате | Верные тип и состояние сохранены, таблица не меняется |
| Состояние не выбрано | Просьба выбрать состояние | Таблица не меняется |

## Клавиатура и фокус

Начальный фокус устанавливается на поле типа. Порядок перехода:

`Тип → Дата → Состояние → Добавить → Применить состояние → Удалить`.

`Shift+Tab` идёт в обратном порядке. Кнопка «Добавить» назначена
кнопкой по умолчанию, поэтому `Enter` отправляет форму. Поля имеют
доступные имена. Ошибка передаётся текстом, доступным для assistive technology,
и видимой рамкой, а не только цветом.

## Исключения и контракт

`Workout` защищает тот же инвариант: тип не пуст и не длиннее 60 символов,
дата и состояние обязательны. Форма заранее проверяет ожидаемые ошибки и
перехватывает только `IllegalArgumentException` от доменного контракта. Общий
`catch (Exception)` не используется: он бы скрыл ошибки программы, не связанные
с вводом пользователя.
