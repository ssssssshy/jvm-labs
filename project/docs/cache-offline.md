# Кэш и автономный режим

Справочник типов тренировок обновляется через `CachedWorkoutTypeDirectory`. За один
цикл выполняется не больше двух сетевых попыток. `AtomicBoolean` не позволяет
запустить второй цикл, пока первый ещё работает.

После успешного HTTP-ответа клиент сначала разбирает и проверяет весь JSON-массив.
Только полный набор передаётся в `WorkoutTypeCache`. Кэш содержит исходное время
получения и записи, поэтому автономный результат можно явно пометить как устаревший.

Запись выполняется в файл в том же каталоге, затем файл заменяется через
`ATOMIC_MOVE`. Если файловая система не поддерживает атомарное перемещение,
используется обычная замена. Некорректный HTTP-статус или JSON возникает раньше
записи и не портит последнюю подтверждённую копию.

| Состояние | Результат |
|---|---|
| Сервер доступен | Полный набор, источник `SERVER`, обновлённый кэш |
| Сервер недоступен | Последний набор, источник `CACHE`, исходное время |
| Первый запуск без кэша | `Нет сохранённых данных. Повторите запрос.` |
| Кэш повреждён | Явная ошибка чтения; повреждение не скрывается |
| Ответ сервера повреждён | Ошибка ответа; хороший кэш остаётся без изменений |

Для персонального журнала тренировок устаревший справочник допустим: он содержит
вспомогательные названия и рекомендуемую длительность, а не критические данные и не
изменяет уже сохранённую историю пользователя. Источник и время показываются,
чтобы пользователь не принял автономную копию за актуальный ответ сервера.
