# Матрица рисков и проверок

Тест выбирается по источнику риска. Предметные правила проверяются без интерфейса,
технологические адаптеры — с настоящими изолированными ресурсами, а основной
пользовательский маршрут — через FXML и контроллер JavaFX.

| Риск | Уровень | Изолированный ресурс | Наблюдаемый результат |
|---|---|---|---|
| Пустой тип создаёт недопустимую тренировку | Unit, модель | Новый объект в тесте | Конструктор отклоняет значение с понятной причиной |
| Ошибка формы частично меняет список | Unit, сервис | Новый `MemoryWorkoutRepository` | Сервис отклоняет ввод, репозиторий остаётся пустым |
| Тесты влияют друг на друга | Unit, сервис | Новая фикстура на тест | Два репозитория имеют независимое состояние |
| Ошибка второй SQL-команды оставляет первую строку | Интеграционный, SQLite | `@TempDir` и настоящая база | Пакет откатывается полностью |
| Повреждённый JSON уничтожает хороший кэш | Интеграционный, HTTP | Локальный `HttpServer` и `@TempDir` | Ошибка видна, содержимое кэша не меняется |
| FXML или обработчик не выполняет основной сценарий | UI-маршрут | JavaFX Application Thread | Кнопка добавляет ровно одну тренировку и выводит сообщение |

`MainUserRouteTest` синхронизируется через `FutureTask` и JavaFX Application Thread.
Фиксированная задержка `sleep` не используется. SQL проверяется настоящим JDBC и
SQLite, а HTTP — настоящим локальным сокетом, поэтому тесты наблюдают кодировку,
сериализацию, ограничения схемы и rollback, которые не способен доказать мок.

HTML-отчёт Gradle после запуска находится в `build/reports/tests/test/index.html`.
Каталог `build` является производным и не включается в сдаваемый комплект; итог
зафиксирован в `evidence/P17_junit.txt`.
