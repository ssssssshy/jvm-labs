# Виртуальные потоки и гонки данных

Два виртуальных потока читают одинаковое значение общего счётчика до барьера, поэтому
обе записи дают `1`. `AtomicInteger.incrementAndGet()` защищает всю операцию и даёт `2`.
Виртуальные потоки не исправляют гонку, потому что меняют стоимость потока, а не правила
доступа к общей памяти.

Диагностические задачи читают неизменяемый снимок `Workout`. Каждый `Future` ожидается,
поэтому результаты и исключения не теряются. Ожидающая задача отменяется с прерыванием,
а `ExecutorService.close()` дожидается завершения.

Один JDBC `Connection` нельзя без явной модели делить между задачами: его транзакционное состояние
общее, а драйвер не обязан делать параллельные операции безопасными. В проекте каждая операция
репозитория открывает своё соединение, а дефицитный ресурс в production ограничивался бы пулом.
