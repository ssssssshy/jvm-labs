# JAR и загрузка расширений

`WorkoutReportProvider` задаёт небольшой контракт отчёта: код, отображаемое название
и формирование строки по списку тренировок. Реализации не создаются в демонстрации
напрямую. `ServiceLoader` читает их имена из
`META-INF/services/ru.npi.workouttracker.extension.WorkoutReportProvider`.

| Поставщик | Код | Результат |
|---|---|---|
| `StatusWorkoutReportProvider` | `status-summary` | Число запланированных и выполненных тренировок |
| `TypeWorkoutReportProvider` | `type-summary` | Число тренировок каждого типа в устойчивом порядке |

Оба класса имеют открытый конструктор без параметров. Клиент зависит только от
интерфейса и может получить новое расширение после добавления реализации и строки
регистрации без изменения цикла загрузки.

## Состав и запуск

Gradle создаёт `build/libs/workout-tracker.jar`. Манифест указывает
`ServiceLoaderDemo` как `Main-Class`, поэтому учебный автономный пример запускается:

```bash
java -jar build/libs/workout-tracker.jar
```

JAR содержит скомпилированные классы, FXML, CSS, SQL-миграции, манифест и описание
сервисов. Он не содержит JDK и сторонние зависимости. Поэтому этот учебный запуск
работает только на установленной Java, а полный переносимый образ приложения будет
создан в P22.

`jdeps` определил прямые модули JDK: `java.base`, `java.desktop`, `java.net.http`,
`java.sql` и `jdk.httpserver`. Классы API и поставщиков в данном запуске загружены
`AppClassLoader` из одного JAR.
